# 缓存与断点续跑的单位是 Snapshot，不是解析结果

落盘缓存的粒度是"某次请求的原始响应"，而不是"解析好的 Record"。理由是解析逻辑一定会改（选择器失效、字段口径调整、语言判定换模型），只要快照还在，改完就能离线重放全部 100 条并对比差异；反过来若缓存的是 Record，旧 bug 会被永久固化，且无法回答"这个粉丝数当时页面上到底写的什么"。

## Considered Options

- **快照缓存（采纳）**：可重放、可审计、可离线测试；代价是磁盘占用更大、需要一次重放成本。
- **结果缓存**：磁盘省、重跑快，但不可重算，也无法作为 Provenance 的证据。
- **不缓存**：每次都打公网，违反"避免无意义重复请求"，且 100 条重复跑会被限流。

## Consequences

- 快照按内容/URL 寻址存放，同一 URL 的多次抓取各自独立，重跑默认复用最近一次。
- 强制刷新是显式开关，而不是默认行为；否则断点续跑形同虚设。
- 测试直接以快照为输入，因此测试不依赖网络，也不会因公网状态变化而变红。
