# 每个 handle 恰好产出一条 Record，失败也写完整字段

输入 100 个 handle，输出就必须是 100 行，不允许"只写成功的那些行"。失败记录同样要填满 15 个必填字段（值为 null / `und` / `[]`），并用 `status` + `error` 说明为什么没有数据。这条契约一旦松动，后续所有统计（覆盖率、状态分布）都会失真，因此不可逆。

## Considered Options

- **全量输出（采纳）**：100 行，行数与输入严格对齐，缺失即有结论。
- **只输出成功行**：文件更小，但直接违反"输入 100 个 handle 在结果中全部出现且无重复"，且丢失失败信息。
- **成功行 + 单独的 failures.jsonl**：多一个文件，验收方需要自己 join，且 100 行的硬要求仍然不满足。

## Consequences

- 采集器内部必须把"没有数据"编码成一条合法的 Record，而不是抛异常中断整个批次。
- `report.json` 的 `result_count` 恒等于 `input_count`，任何不等都说明流程有 bug。
