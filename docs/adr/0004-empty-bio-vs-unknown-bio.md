# bio 用三值表达：空串、null、有值

`bio` 只有 string|null 两种 JSON 类型，却要承载三种事实：**确实为空**、**没采到**、**有内容**。约定：`status=ok` 且页面明确显示无简介 → `bio=""`；没采到或账号不可见 → `bio=null`（同时 `status` 非 ok）；其余 → 原文。这条约定直接对应验收项"空简介与采集失败需要区分"，属于对外契约，改起来会同时影响报告口径与抽样复核，故记录在案。

## Considered Options

- **空串 / null 三值（采纳）**：不新增字段即可区分，且符合 JSON 语义。
- **统一用 null 表示空**：最简单，但直接违反验收要求。
- **新增 `bio_state` 字段（present/empty/unknown）**：表达最清晰，但把语义放进扩展字段会让只读必填字段的验收方看不到区别；可作为补充，不能替代三值约定。

## Consequences

- 空串只在 `ok` 记录中出现；`null` 只在非 `ok` 记录中出现，可作为一致性断言来测试。
- 报告中的 bio 覆盖率按"非 null"统计，`""` 计入覆盖（它是一次成功观测）。
