# 只采无登录即可访问的公开页面

本题的合规红线是"不得绕过验证码、访问控制、付费墙或平台安全限制"，因此采集一律以**未登录、无凭据的匿名请求**发起：不发 Cookie，不带账号态，遇到登录墙就返回 `blocked` 而不是想办法绕过去。这个决定几乎不可逆（一旦引入登录态，整条链路的合规性论证就失效了），且未来维护者看到"成功率只有 60%"时最想做的事恰恰是"加个 Cookie 吧"，所以必须留下记录。

## Considered Options

- **匿名请求（采纳）**：合规成本最低，代价是 `private` / `blocked` 比例偏高。
- **登录态 + Cookie**：覆盖率显著更高，但违反题目约束，且 Cookie 本身就是禁止入库的凭据。
- **第三方聚合 API / 镜像站**：看似绕开限制，实质上多数需要密钥或依赖他人违规抓取，无法证明来源合法性。

## Consequences

- 失败不是缺陷，是预期输出的一部分；`blocked` 与 `private` 的数量应当被统计而不是被消除。
- 任何"提升成功率"的改动都必须先过一遍本条：它是否在绕过访问控制。
